Test: `tests/test_inventory_hosts.py::test_docker_host_preserves_only_configured_user`. |

| `CONN-CONTAINER-MANAGER-MCP-R007` | **Destructive confirmation fails closed.** Every destructive action of `cm_image_operations`, `cm_container_operations`, `cm_volume_operations`, `cm_network_operations`, `cm_swarm_operations` and `cm_system_operations` (remove, prune, swarm init and leave, service and node remove, system prune) goes through the SDK `ctx_confirm_destructive` with an explicit `confirm` argument. A caller that passes `confirm=true` is confirmed. A client that cannot elicit and did not confirm gets a clean `cancelled` refusal naming `confirm=true`, and the manager is not reached. A missing context never skips the confirmation. Caller chain: MCP tools cm_image_operations (mcp_server.py L316), cm_container_operations, cm_volume_operations, cm_network_operations, cm_swarm_operations, cm_system_operations -> mcp_server.py::_confirm_or_refuse (L75) -> scion_sdk.mcp.context.ctx_confirm_destructive and confirmation_refusal. Shape: one helper, mcp_server.py::_confirm_or_refuse, returns None when confirmed or a cancelled refusal naming confirm=true; every destructive action calls it before touching the manager; verbose-tier prunes are marked destructive in surface.py::_destructive. | `tests/test_destructive_confirmation_transports.py` proves it over stdio, HTTP without auth and JWT HTTP. Test: `tests/test_destructive_confirmation_transports.py::test_prune_and_swarm_tools_require_confirmation`. |
